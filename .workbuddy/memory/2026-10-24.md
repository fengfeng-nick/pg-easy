## 把 360-qa 的 4.9G dump 导入本地 Docker Postgres

- 源文件：`~/Downloads/public.sql`（Navicat 导出，源库 360-test/public，4.9G，585 表，341 万条单行 INSERT，无 COPY、无 SET、无 CREATE DATABASE）。
- 目标：容器 `postgres18`（postgres:18，root/root，端口 5432）→ 新建库 `pg360`（UTF8，owner root），并建角色 `"360"`（dump 里 715 处 `OWNER TO "360"`，LOGIN/密码 360）。
- 必装扩展（dump 不含 `CREATE EXTENSION`）：`uuid-ossp`（441 处 `uuid_generate_v4()`）、`pgcrypto`、`pg_trgm`、`btree_gin`、`unaccent`、`vector`（表 `crm_sales_clue_vector` 用 `vector(1536)`，但该表本身无数据）。
- 正确流程：`docker cp` 进容器 → `psql -q -v ON_ERROR_STOP=0 -f` + `PGOPTIONS="-c synchronous_commit=off -c jit=off -c maintenance_work_mem=1GB -c client_min_messages=warning"`（不抑制 NOTICE 会刷出几十万行 `DROP ... IF EXISTS` 提示）。耗时约 4 分 46 秒。
- 结果核对：585 表 / 3,414,563 行（与 dump 的 INSERT 条数**完全一致**）/ 3.3G / 4545 索引 / 1270 外键 / 155 视图 / 92 枚举。仅 23 条 ERROR，其中 21 条是 Navicat 把 uuid-ossp 的函数当用户函数重放导致的冲突（无害）。
- 后续坑：dump 里没有 `setval`，导入后已用 DO 块把 8 个自建序列 `setval` 到 `max(列值)`，否则后续 INSERT 会撞主键。`ANALYZE` 也补跑了。
- 环境坑：容器内 `apt-get update` 会因锁/网络长时间挂住，`pkill -9 -x apt-get` + 删 `/var/lib/{apt,dpkg}/lock*` 后可直接用镜像里已有的 pgdg 索引装包。
